# DIYP 列表与节目单

`diyp.py` 只是 DIYP 的适配参考。APTV 这类可以直接使用现有 M3U 的播放器不需要它。

## 本地运行

需要 Python 3，无需安装第三方 Python 包。先用 `iptv.py` 生成配置目录，再在脚本目录启动：

```sh
cd yehbp/assets/iptv
python3 diyp.py config=tel
```

`config=tel` 与 `iptv.py` 相同，相对路径以脚本目录为基准，只读取其中已有的 `playlist.m3u`。它不读取运营商凭据，不鉴权，也不刷新 `iptv.py` 的数据。默认监听 `0.0.0.0:5142`。`--host`、`--port`、`--public-base` 都可省略。启动后保持终端开启，按 `Ctrl+C` 停止服务。

在运行机器的浏览器中打开 `http://127.0.0.1:5142/tel.m3u`，可查看生成的列表；打开 `http://127.0.0.1:5142/tel.epg?ch=频道名&date=YYYY-MM-DD`，可查看节目单 JSON，请替换频道名和日期。

## DIYP 配置

电视访问时，将下面的“访问地址”替换为运行脚本的电脑或服务器的局域网 IP；不要填写 `127.0.0.1`。电视需要能访问该机器的 5142 端口。

DIYP 里列表和 EPG 分开填写：

- 列表：`http://访问地址:5142/tel.m3u`
- EPG：`http://访问地址:5142/tel.epg`

`/tel.m3u` 只是按配置命名的接口。返回内容仍是 DIYP 需要的“分组、频道名,播放地址”文本，并不是把内容转换成 M3U；`.m3u` 不能证明电视已按 M3U 解析。频道地址按这次访问自动生成。有回看地址的频道使用 `/PLTV/序号/分组/名称`，没有的仍使用 `/c/序号/分组/名称`。DIYP 只根据地址里的 `/PLTV/` 显示回看；回看时它会把该段换成 `/TVOD/`，并追加 `playseek=14位-14位`。`/c/` 仍可直接播放直播。前面有路径前缀时，加 `--public-base http://访问地址/路径前缀`。

它只读取现成 `playlist.m3u`。播放列表约每 300 秒按文件修改时间检查，内容没变不重读。节目单来自 M3U 头部的 `x-tvg-url`：`http` 或 `https` 地址按原样请求；`epg.xml` 这类相对地址按 `playlist.m3u` 所在目录解析，不使用 `file://` 作为电视配置。默认每 3600 秒再请求一次；只改播放列表、EPG 地址不变时，不会因此提前重下这些源。EPG 地址变了，下一次列表检查读入后会按新地址更新。`--refresh` 只改 EPG 间隔，默认 3600，列表检查固定 300 秒。`iptv.py` 生成的 `tel/epg.xml` 可由相对引用读到，DIYP 对外入口仍是 `/tel.epg`，不需要第二份运营商配置。

源暂时打不开时沿用该地址上一份磁盘缓存，没有缓存就返回空节目。缓存文件本身没有过期上限，但默认放在系统临时目录，可能被系统清理。回看只接受 `playseek=14位-14位`。这里只检查 HTTP 跳转和节目单响应，电视能否播放需在 DIYP 上另测。配置名换成别的时，两个入口分别是 `/<config>.m3u` 和 `/<config>.epg`。
